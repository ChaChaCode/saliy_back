# Telegram через Cloudflare Worker

С сервера в РФ (Timeweb, 188.225.33.32) `api.telegram.org` открывается нестабильно: 08.11.2026 весь день падали `getUpdates`, а вход в админку через Telegram работал с перебоями. Поэтому бэкенд может ходить в Telegram через релей на Cloudflare:

сервер → Cloudflare Worker → api.telegram.org

## Как устроено в бэкенде

- Все запросы к Bot API собирают адрес через одну функцию (`src/common/utils/telegram-api.ts`): вход админа, уведомления о блокировке входа, кнопки бота, long polling `getUpdates`, бэкапы базы в Telegram.
- Адрес релея задаётся переменной `TELEGRAM_API_BASE`, формат: адрес воркера и секрет первым сегментом пути. Пустая переменная, адрес не по https или с query — запросы идут напрямую в `api.telegram.org`.
- У каждого запроса в Telegram есть таймаут: обычные 10 с, `getUpdates` 45 с (Telegram держит соединение до 30 с), отправка бэкапа 120 с.

## Воркер

- Код воркера — `deploy/cloudflare-tg-worker.js`. Он пропускает только запросы с секретом в пути и только к Bot API (`/bot…`, `/file/bot…`), лишние заголовки не передаёт.
- Секрет — переменная воркера `PATH_SECRET` с типом **Secret**, не короче 24 символов (латиница, цифры, `_`, `-`). Тот же секрет стоит в конце `TELEGRAM_API_BASE` на сервере.
- Логи воркера (Settings → Observability) выключены: токен бота — часть адреса запроса и сохранился бы в логах Cloudflare.
- Бесплатный тариф Cloudflare — 100 000 запросов в сутки на аккаунт. Long polling — примерно 3 000 запросов в сутки.

## Включение и откат

- Включить: проверить с сервера запрос `getMe` через адрес воркера, затем прописать `TELEGRAM_API_BASE` в `.env` и перезапустить бэкенд с перечитыванием `.env`.
- Откатить: очистить `TELEGRAM_API_BASE` и перезапустить — бэкенд снова пойдёт напрямую.
