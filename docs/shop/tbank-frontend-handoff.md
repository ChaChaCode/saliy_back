# Т-Банк: актуальный контракт frontend

Актуализировано **8 ноября 2026**. Общий контракт витрины и админки:
[frontend-handoff.md](frontend-handoff.md). Это текущая инструкция;
первоначальный план перехода от 31 октября больше не описывает состояние магазина.

## Текущее состояние

Т-Банк включён в рабочем магазине. Боевой терминал подключён 3 ноября,
первый реальный платёж подтверждён — см. [отчёт](../tbank-production-2026-11-03.md).
При актуализации документации проверен рабочий
`GET /api/orders/delivery-options?country=RU`:

```json
{
  "deliveryTypes": ["CDEK_PICKUP", "STANDARD"],
  "paymentMethods": ["CARD_ONLINE"],
  "country": "RU"
}
```

Для новых покупок отправлять только `CARD_ONLINE`, отображать «Т-Банк».
Прежние способы оплаты нужны для истории заказов; не показывать их в новой форме
и не восстанавливать из сохранённого состояния checkout.

## Оформление

| Запрос | Поведение frontend |
| --- | --- |
| `GET /api/orders/delivery-options?country=RU` | Получить доступные способы; не зашивать цену доставки |
| `POST /api/orders/calculate` | Передать товары, доставку и `paymentMethod: 'CARD_ONLINE'`; показать серверный итог |
| `POST /api/orders` | Создать заказ тем же составом и контактами; получить `orderNumber`, `paymentUrl`, `isPaid`, `status` |
| `GET /api/orders/:orderNumber` | После возврата из банка читать фактическое состояние заказа |

Схема тела расчёта и создания — [orders.md](orders.md). Не передавать цену
товара или итог как доверенные значения: backend рассчитывает их заново.

Пример фрагмента ответа создания, не реальная ссылка:

```json
{
  "orderNumber": "<номер из API>",
  "paymentMethod": "CARD_ONLINE",
  "status": "PENDING",
  "isPaid": false,
  "paymentUrl": "https://pay.tbank-online.com/<идентификатор>"
}
```

Проверить URL как HTTPS-ссылку разрешённого платёжного домена и переходить
на полученное значение. Не собирать ссылку самостоятельно. Для маршрута магазина
использовать `orderNumber`, не банковский `PaymentId` и не внутренний UUID.

## Возврат из банка

1. Открыть `/order/:orderNumber` и запросить заказ.
2. Подтверждение оплаты — серверное `isPaid: true`, с учётом текущего `status`.
   Оплаченный предзаказ может иметь статус `AWAITING_PREORDER`, см. [предзаказы](preorders.md).
3. `PENDING`/`isPaid: false` — показать ожидание и ограниченный опрос API.
   Практический вариант для клиента: каждые 3–5 секунд до 60 секунд, затем
   кнопка повторной проверки. Это рекомендация интерфейса, не таймер backend.
4. `PAYMENT_FAILED`/`CANCELLED` — показать неуспешный результат и возврат
   к оформлению нового заказа. Не обещать повторную оплату старой ссылки.
5. JSON `null`, `404`, потеря сети — отдельные состояния; не показывать успех.
6. После подтверждения перечитать корзину и заказ; не очищать корзину только
   из-за перехода на страницу `/success`.

Публичного `POST /api/payment/tbank/check-status` нет. Браузер не вызывает
API банка и webhook. Backend принимает `POST /api/payment/tbank/webhook`,
проверяет данные и дополнительно опрашивает незавершённые платежи.
`AUTHORIZED` не означает подтверждённое списание; backend подтверждает оплату
по `CONFIRMED`. `REFUNDED` — отдельное состояние возврата.

## Авторизация и защита данных

Использовать `/api` нового домена и Better Auth cookie с `credentials: 'include'`.
Публичный ответ заказа гостю может не содержать имя, email, телефон и адрес;
страница результата должна работать без этих полей.
Не передавать в браузер пароль терминала, банковские токены или секрет webhook.

## Проверки frontend

- Гостевой и авторизованный checkout отправляют `CARD_ONLINE`.
- Старое состояние localStorage не возвращает Точку/Яндекс Пэй в новую форму.
- Используются серверные итоги, в том числе новая пара `price`/`oldPrice`.
- Возврат до webhook показывает ожидание, а не ложный успех.
- Обрабатываются неизвестный заказ, ошибка сети, отказ и отмена.
- `isPaid: true` + `AWAITING_PREORDER` показывают оплаченный предзаказ,
  а не ошибку оплаты или готовую отправку.

Новая реальная оплата при изменениях 8 ноября не выполнялась. Добавление
старой цены не меняет банковский протокол. Подробности backend и ограничения
фискализации/возвратов — [payment.md](payment.md).
