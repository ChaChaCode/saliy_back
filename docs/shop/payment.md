# Оплата через Т-Банк

Задачи и контракт для frontend-разработчика: [переход на Т-Банк](./tbank-frontend-handoff.md).

31 октября 2026 backend выложен с единственным методом `CARD_ONLINE` в режиме DEMO.
Подробности и ограничения: [отчёт о выкладке](../tbank-deployment-2026-10-31.md).

3 ноября 2026 включён боевой терминал, первый реальный заказ оплачен:
[отчёт о переходе на боевой терминал](../tbank-production-2026-11-03.md).

Единственный способ оплаты при оформлении: `CARD_ONLINE`. GET /api/orders/delivery-options возвращает только его. Остальные методы отклоняются до создания заказа. Старые значения enum сохранены для истории заказов и ручных заказов менеджера; старые интеграции удалены.

POST /api/orders возвращает paymentUrl формы Т-Банка. Заказ остаётся PENDING до подтверждения банком. Переход на страницу успеха не подтверждает оплату.

Настройки: TBANK_TERMINAL_KEY, TBANK_PASSWORD (только в .env), TBANK_BASE_URL=https://securepay.tinkoff.ru/v2, TBANK_POLLING_ENABLED=true. DEMO — тестовый терминал (ключ с суффиксом DEMO), реальные карты он отклоняет. С 3 ноября 2026 на сервере боевой терминал. После смены ключей процесс перезапускается с окружением, загруженным из `.env` (см. отчёт от 3 ноября), и ключ сверяется в окружении работающего процесса.
BACKEND_URL должен содержать публичный адрес API с /api, FRONTEND_URL — адрес магазина.

POST /api/payment/tbank/webhook принимает JSON, проверяет SHA-256 Token, терминал и сверяет PaymentId, OrderId и сумму через GetState. Ответ при успехе: HTTP 200, текст OK. При ошибке возвращается ошибка, чтобы банк повторил уведомление. Каждую минуту статус PENDING дополнительно проверяется через API. При неверной подписи в лог пишутся только имена и типы полей уведомления, его Status и TerminalKey — без значений Pan и Token.

Платёж одностадийный (PayType=O); только CONFIRMED подтверждает заказ. AUTHORIZED не означает списание. REFUNDED означает полный возврат. Частичные возвраты не помечают заказ полностью возвращённым. Возврат денег запускается из админки кнопкой «Вернуть деньги» через метод Т-Банка Cancel (см. [Admin/orders.md](../Admin/orders.md), раздел 7); сумма возвратов хранится в `refundedAmount`.

При отказе (REJECTED) или отмене платежа, а также при ошибке Init заказ получает PAYMENT_FAILED или CANCELLED, и товар сразу возвращается на склад: кнопка «Оплатить снова» ведёт в checkout, то есть покупатель оформляет новый заказ. Возврат остатков выполняется атомарно и только для заказа в статусе PENDING, поэтому повторное уведомление не вернёт товар дважды. Если оплата придёт после отказа или автоотмены, заказ восстанавливается как оплаченный и товар списывается снова.

Срок ссылки задаёт ORDER_PAYMENT_LINK_TTL_MIN, автоотмену — ORDER_PENDING_TIMEOUT_MIN. Корневой сертификат Минцифры из certs подключается только к HTTP-клиенту банка с сохранением проверки TLS.

Фронтенд должен отправлять CARD_ONLINE и показывать название «Т-Банк» вместо старых Точки и Сплита. Фронтенда в этом репозитории нет.

Фискализация Receipt не добавлена: параметры кассы, налогообложения и НДС не заданы. Email-подтверждение заказа не является фискальным чеком.

Документация: https://developer.tbank.ru/eacq/api/init и https://developer.tbank.ru/eacq/intro/developer/notification
