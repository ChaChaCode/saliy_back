# API авторизации

Вход покупателей — по 4-значному коду из письма через Better Auth.
Базовый адрес API: `https://saliyclothes.com/api`.

С 4 ноября 2026 это единственный способ входа: прежние эндпоинты
`/api/auth/send-code`, `/api/auth/verify-code`, `/api/auth/refresh` и
`/api/auth/logout`, JWT покупателей и таблицы `RefreshToken`/`VerificationCode`
удалены.

## Вход и выход

Эндпоинты, тела запросов, ответы и ошибки — в [better-auth.md](./better-auth.md):

| Действие | Эндпоинт |
|---|---|
| Отправить код | **POST** `/api/session/email-otp/send-verification-otp` |
| Войти по коду | **POST** `/api/session/sign-in/email-otp` |
| Проверить сессию | **GET** `/api/session/get-session` |
| Выйти | **POST** `/api/session/sign-out` |

Профиль, адрес доставки и аватар — по адресам `/api/auth/me`, `/api/auth/profile`,
`/api/auth/delivery-location`, `/api/auth/avatar`, см. [user.md](./user.md).

## Сессия

- Одна httpOnly + Secure кука `__Secure-saliy.session_token`, подписанная секретом
  `BETTER_AUTH_SECRET`. JavaScript страницы её не видит.
- Срок 7 дней, продлевается не чаще раза в сутки, пока покупатель заходит на сайт.
- Сессия хранится в таблице `auth_sessions`; выход отзывает её.
- Заголовок `Authorization` не принимается.
- Защищённые маршруты (профиль, корзина, заказы покупателя, отзывы, промокоды
  авторизованных) проверяют сессию Better Auth; без неё отвечают 401.

## Политика SameSite для cookie

Атрибут SameSite у куки сессии управляется переменной окружения `COOKIE_SAMESITE`:

| Значение | Когда использовать |
|----------|--------------------|
| lax (по умолчанию) | Фронт и API на одном сайте (saliyclothes.com и его поддомены). Строже и безопаснее. |
| none | Фронт на другом домене (cross-site). Браузер отправляет cookie на cross-site запросы; требует HTTPS. |
| strict | Максимально строгий режим. |

Кука ставится без атрибута Domain — привязана к хосту, который её выдал.

## Сценарий

1. Отправить код на почту.
2. Войти по коду из письма — backend ставит куку сессии.
3. Обращаться к защищённым эндпоинтам — браузер сам отправляет куку
   (при cross-origin запросах — с передачей учётных данных).
4. Обновлять ничего не нужно: сессия продлевается сама.
5. Выйти — сессия отзывается, кука удаляется.

## Коды ошибок

| Код | Описание |
|-----|----------|
| 200 | Успешно |
| 400 | Некорректные данные, неверный или истёкший код |
| 401 | Нет сессии |
| 403 | Исчерпаны попытки ввода кода; запрос с чужого домена |
| 429 | Слишком частые запросы |
| 500 | Ошибка сервера |
