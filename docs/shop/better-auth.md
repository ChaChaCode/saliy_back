# Вход покупателей через Better Auth

Вход покупателей по коду из письма — через Better Auth на `/api/session/*`.
Переход завершён 4 ноября 2026: витрина входит через Better Auth, прежние
эндпоинты `/api/auth/send-code`, `/api/auth/verify-code`, `/api/auth/refresh`,
`/api/auth/logout` удалены.

## Статус

- 3 ноября 2026 — backend с Better Auth выложен (этап 1), оба способа входа работали.
  Вход проверен на реальной базе.
- 3 ноября 2026, 21:15 — витрина переведена на `/api/session/*`.
- 4 ноября 2026 — этап 2: удалены прежние эндпоинты входа, JWT покупателей,
  passport и таблицы `RefreshToken`/`VerificationCode`. Оставшиеся старые сессии
  (12 у 4 покупателей) сброшены по решению владельца — эти покупатели один раз
  вошли по коду заново.

Первая попытка выкладки в 18:26 откатана через 2–3 минуты: флаг
`disableGlobalAuthGuard` был передан внутрь `useFactory`, где пакет его не читает,
и все маршруты API отвечали 401. Флаг перенесён на верхний уровень
`forRootAsync`; там же исправлена генерация id (`generateId` должен возвращать
строку: у таблиц `auth_*` нет значения по умолчанию в БД). Обе ошибки теперь
ловит `scripts/better-auth-e2e.ts` и предполётная проверка новой сборки на
отдельном порту с реальной базой перед переключением.

## Что меняется для витрины

- Вход, выход и проверка сессии идут через `/api/session/*`.
- Сессия — одна httpOnly-кука, её ставит и продлевает backend. Обновлять токен
  вручную не нужно: эндпоинта refresh больше нет, повтор запросов после 401
  не нужен.
- Профиль, адрес доставки, аватар, корзина, заказы — без изменений, по прежним
  адресам (`/api/auth/me`, `/api/auth/profile` и т. д.). Использовать текущую
  сессию Better Auth; поддержка прежнего JWT-входа удалена 4 ноября.
- Отправлять заголовок `Authorization` не нужно и бесполезно: он не принимается.

Можно использовать официальный клиент Better Auth для React (пакет `better-auth`,
клиент с плагином Email OTP) с адресом `https://saliystudio.com` и путём
`/api/session`, либо вызывать эндпоинты напрямую — ниже описаны оба как HTTP.

Все запросы — с передачей кук (режим включения учётных данных) и с заголовком
`Origin` сайта: браузер ставит его сам. Запросы с чужого домена отклоняются (403).
Разрешённые домены — из `CORS_ORIGINS` backend.

## Эндпоинты

### 1. Отправить код

**POST** `/api/session/email-otp/send-verification-otp`

Тело: `email` и `type` со значением `sign-in`.

- Ответ `200`. Письмо с 4-значным кодом уходит на почту — то же письмо, что и раньше.
- Код действует 10 минут, на него 10 попыток ввода.
- Не больше 3 отправок в минуту с одного IP, иначе `429`
  с сообщением «Too many requests. Please try again later.».

### 2. Войти по коду

**POST** `/api/session/sign-in/email-otp`

Тело: `email` и `otp` (код из письма).

- Ответ `200`: в теле объект пользователя Better Auth и `token`; кука сессии
  ставится в ответе. **`token` не сохранять и никуда не отправлять**: без подписи
  из куки он не даёт входа, а держать его в JavaScript незачем.
- Если покупателя с такой почтой нет, он создаётся автоматически (как раньше).
- Гостевые заказы на эту почту привязываются к покупателю (как раньше).
- После успешного входа данные профиля брать из **GET** `/api/auth/me`:
  в объекте пользователя Better Auth только базовые поля.
- После входа, как и раньше, слить гостевую корзину: **POST** `/api/cart/merge`.

Ошибки (в теле `message` и `code`):

| Ситуация | Статус | `code` |
|---|---|---|
| Неверный код или у почты нет активного кода | 400 | `INVALID_OTP` |
| Код истёк | 400 | `OTP_EXPIRED` |
| Исчерпаны 10 попыток — нужен новый код | 403 | `TOO_MANY_ATTEMPTS` |
| Больше 10 попыток входа в минуту с IP | 429 | — |

### 3. Проверить сессию

**GET** `/api/session/get-session`

- Гость: `200` и `null` (не 401 — для гостей это не ошибка).
- Вошедший: `200`, объект с `session` и `user`. Для данных профиля по-прежнему
  использовать `/api/auth/me`.
- Сессия живёт 7 дней и продлевается сама не чаще раза в сутки, пока покупатель
  заходит на сайт.

### 4. Выйти

**POST** `/api/session/sign-out` (пустое тело) — `200`, кука удаляется, сессия
в базе отзывается.

## Что убрать из витрины после перехода

- Вызовы `/api/auth/send-code`, `/api/auth/verify-code`, `/api/auth/refresh`,
  `/api/auth/logout`.
- Логику обновления токена и повтора запроса после 401.
- Вызов refresh при открытии страницы: вместо него `get-session`.

1. Backend с Better Auth выложен (оба способа входа работали).
2. Витрина перешла на `/api/session/*`.

## Проверка

- Вход: код приходит, вход по нему, `/api/auth/me` отдаёт профиль.
- Неверный код → `INVALID_OTP`; после 10 неверных → `TOO_MANY_ATTEMPTS`.
- Обновление страницы — покупатель остаётся в аккаунте; гость — `get-session` даёт `null`.
- Выход — `/api/auth/me` отвечает 401.
- Гостевые заказы на ту же почту появляются в «Моих заказах» после входа.
- Корзина гостя сливается после входа.
