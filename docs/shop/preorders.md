# Предзаказы

Предзаказ оплачивается полностью при оформлении через существующий платёжный поток Т-Банка и ждёт готовности товара. Магазин сообщает о готовности отдельно. Физический склад и свободные места в будущей партии учитываются отдельно. Весь заказ, включая обычные товары, отправляется одной посылкой после готовности всех предзаказов.

## Настройка товара

В API товаров и админки добавлены поля:

```json
{
  "cardStatus": "PRE_ORDER",
  "stock": { "S": 0, "M": 0 },
  "preorderStock": { "S": 10, "M": 20 }
}
```

- `preorderStock` — **оставшееся** количество мест по размерам, целые неотрицательные числа. Это не общий объём партии. При редактировании не прибавляйте уже зарезервированные места повторно.
- Товар с `PRE_ORDER` покупается из `preorderStock`, даже если физический `stock` положительный. Для обычных товаров используется `stock`.
- С нулевым/неуказанным лимитом покупка предзаказа запрещена. Старым карточкам `PRE_ORDER` нужно настроить лимиты после обновления.
- Multipart API админки принимает `preorderStock` JSON-строкой.
- У товара поддерживается одна открытая партия предзаказа. Не заменяйте её лимиты новой партией, пока прежние резервы не выполнены или не отменены.

## Корзина и оформление

Валидация корзины, расчёт и создание заказа возвращают у позиций `isPreorder`. У корзины дополнительно есть `canPurchase` и `availableQuantity` — количество доступных мест или физических единиц в зависимости от типа товара. Для совместимости `inStock` в валидации корзины также означает достаточное количество для покупки, включая лимит предзаказа.

`GET /api/products/:id/stock?size=M` сохраняет физические `inStock`/`quantity`, дополнительно возвращая `isPreorder`, `availableQuantity`, `canPurchase`. У предзаказа `inStock: false` и `canPurchase: true` — допустимое сочетание. Фильтр каталога `inStock=true` по-прежнему означает физическое наличие.

Перед оплатой витрина должна показывать:

1. «Предзаказ. Оплата 100% при оформлении».
2. «О готовности к отправке сообщим отдельно».
3. «Весь заказ отправляется вместе после поступления товаров», если есть хотя бы один предзаказ.
4. Для недоступных позиций блокировать оформление по `canPurchase`, а не только по физическому остатку.

При оформлении лимит резервируется в транзакции. Проверка повторяется под блокировкой строк товаров, поэтому два покупателя не могут занять последнее место одновременно. Повторяющиеся позиции одного размера в заказе объединяются. Ошибка регистрации платежа, отказ или таймаут возвращают резерв. Корзина сама по себе места не резервирует.

В `OrderItem` сохраняются `isPreorder` и `preorderReady`. Смена `cardStatus` у товара не меняет существующие заказы. Ручные заказы менеджера поддерживают те же правила. При редактировании состава сохранённый тип существующих предзаказов сохраняется.

## Оплата и отправка

После оплаты заказ с неготовыми предзаказами получает статус `AWAITING_PREORDER` («Оплачен, ожидает поступления»). Обычные заказы переходят в `CONFIRMED`, как раньше. Повторное уведомление об оплате не повторяет списание и отправку письма. Письмо об оплате содержит отметку предзаказа и текст «О готовности к отправке сообщим отдельно».

Автоматическое, ручное и массовое создание накладных СДЭК блокируется, пока хотя бы одна позиция предзаказа не готова. Нельзя обойти это обычным изменением статуса заказа на отправленный.

Когда партия поступила:

1. Занести фактически поступившее количество в `stock` товара. До выделения оплаченных предзаказов оставить карточку в `PRE_ORDER`, чтобы обычные покупки не расходовали физический остаток.
2. В порядке очереди вызвать `POST /api/admin/orders/:orderNumber/preorder-ready` без тела для оплаченных заказов.
3. Команда атомарно проверит наличие всех предзаказанных размеров, выделит их из `stock`, установит `preorderReady: true` и переведёт заказ в `CONFIRMED`. Уже зарезервированные обычные позиции второй раз не списываются. Если чего-то не хватает, вся операция откатывается.
4. Покупателю отправляется письмо о готовности предзаказа к отправке. Для СДЭК создаётся накладная. Если СДЭК недоступен, готовность сохраняется, ответ содержит `cdekSyncError`; создание накладной можно повторить существующей командой админки.
5. После выделения предзаказов можно сменить карточку на обычный статус и продавать оставшийся `stock`.

Повторный вызов готовности отклоняется. Для отправки требуется подтверждение менеджера и реальные остатки.

## Отмена и возврат

При отмене неготовой позиции возвращается место в `preorderStock`, а после готовности — физический `stock`. Повторная отмена/возврат не возвращает резерв второй раз (`inventoryReleased`). Подтверждённый платёжной системой возврат до поступления освобождает места и обычные позиции смешанного заказа.

Существующая команда возврата админки **фиксирует выполненный возврат**, но не отправляет деньги через API банка. Деньги возвращаются в кабинете банка или вручную для соответствующего способа оплаты. Отмена оплаченного заказа также сама по себе не возвращает деньги. При отмене оплаченного предзаказа клиент получает письмо с предложением связаться с магазином по вопросу возврата.

Если оплата поступила после автоматической отмены, резерв восстанавливается по сохранённому типу позиции. Если места уже заняты, факт оплаты сохраняется, заказ получает `PROCESSING`, `inventoryReleased: true` и причину с требованием проверки менеджера. Создание накладной и готовность блокируются: менеджер должен связаться с покупателем и оформить возврат либо решить вопрос с наличием.
