# Предзаказы

Предзаказ — это товар, которого ещё нет на руках, но его уже можно купить. Он оплачивается полностью при оформлении через Т-Банк и ждёт поступления. Магазин сообщает о готовности отдельно. Весь заказ, включая обычные товары, отправляется одной посылкой после поступления всех предзаказов.

## Настройка товара

Предзаказ настраивается так же, как обычный товар, плюс статус карточки:

```json
{
  "cardStatus": "PRE_ORDER",
  "stock": { "S": 10, "M": 100 }
}
```

- `stock` у предзаказа — **сколько можно предзаказать** по размерам. «M — 100» значит, что предзаказать можно ровно 100 штук M; на 101-ю бэкенд откажет.
- Каждый оформленный предзаказ уменьшает `stock`, как обычная покупка. Отменённый или неоплаченный предзаказ возвращает количество.
- Отдельного лимита предзаказа нет. До 8 ноября 2026 был `preorderStock`; он удалён миграцией `20261108120000_drop_preorder_stock`, теперь используется только `stock`.
- `PRE_ORDER` отличается от обычного товара только тем, что заказ ждёт поступления: статус заказа, тексты перед оплатой и отправка после подтверждения менеджером (см. ниже).

## Корзина и оформление

Валидация корзины, расчёт и создание заказа возвращают у позиций `isPreorder`. У корзины есть `canPurchase` и `availableQuantity` — сколько можно купить из `stock`. Витрина опирается на них и сама ничего не считает.

`GET /api/products/:id/stock?size=M` возвращает `inStock`/`quantity`, а также `isPreorder`, `availableQuantity`, `canPurchase`.

Перед оплатой витрина должна показывать:

1. «Предзаказ. Оплата 100% при оформлении».
2. «О готовности к отправке сообщим отдельно».
3. «Весь заказ отправляется вместе после поступления товаров», если есть хотя бы один предзаказ.
4. Для недоступных позиций блокировать оформление по `canPurchase`.

При оформлении количество списывается из `stock` в транзакции под блокировкой строк товаров, поэтому два покупателя не могут занять последнюю единицу одновременно. Повторяющиеся позиции одного размера в заказе объединяются. Ошибка регистрации платежа, отказ или таймаут возвращают количество. Корзина сама по себе ничего не резервирует.

В `OrderItem` сохраняются `isPreorder` и `preorderReady`. Смена `cardStatus` у товара не меняет существующие заказы. Ручные заказы менеджера поддерживают те же правила.

## Оплата и отправка

После оплаты заказ с непоступившими предзаказами получает статус `AWAITING_PREORDER` («Оплачен, ожидает поступления»). Обычные заказы переходят в `CONFIRMED`, как раньше. Письмо об оплате содержит отметку предзаказа и текст «О готовности к отправке сообщим отдельно».

Создание накладной СДЭК (автоматическое, ручное и массовое) блокируется, пока предзаказ не отмечен поступившим. Обойти это сменой статуса на «отправлен» нельзя.

Когда партия поступила:

1. Для оплаченных заказов вызвать `POST /api/admin/orders/:orderNumber/preorder-ready` без тела.
2. Команда отмечает позиции предзаказа `preorderReady: true` и переводит заказ в `CONFIRMED`. Остатки она **не меняет**: товар уже списан из `stock` при оформлении.
3. Покупателю отправляется письмо о готовности. Для СДЭК создаётся накладная; если СДЭК недоступен, готовность сохраняется, ответ содержит `cdekSyncError`, накладную можно создать повторно командой админки.
4. Когда все предзаказы отправлены, карточку можно перевести в обычный статус и продавать как обычный товар.

Повторный вызов готовности отклоняется.

## Отмена и возврат

При отмене или возврате количество возвращается в `stock` — и до поступления, и после. Повторная отмена/возврат не возвращает количество второй раз (`inventoryReleased`).

Команда возврата админки **фиксирует выполненный возврат**, но не отправляет деньги через API банка: деньги возвращаются в кабинете банка. Отмена оплаченного заказа сама по себе деньги не возвращает. При отмене оплаченного предзаказа клиент получает письмо с предложением связаться с магазином по вопросу возврата.

Если оплата пришла после автоматической отмены, количество снова списывается. Если его уже не осталось, факт оплаты сохраняется, заказ получает `PROCESSING`, `inventoryReleased: true` и причину с требованием проверки менеджера; накладная и готовность блокируются до решения менеджера.
