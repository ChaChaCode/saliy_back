# Подключение saliystudio.com — 7 ноября 2026

На сервере `188.225.33.32` настроены:

- `https://saliystudio.com` и `https://www.saliystudio.com` — магазин Next.js.
- `https://admin.saliystudio.com` — админка Vite.
- `/api/` у магазина и админки — существующий NestJS backend.

DNS всех трёх имён указывает на `188.225.33.32`. Для новых доменов добавлены отдельные конфигурации Nginx, старые адреса сохранены. HTTP перенаправляет на HTTPS.

## HTTPS и Nginx

Сертификат Let's Encrypt покрывает основной домен, `www` и `admin`; срок действия до 5 февраля 2027. Проверка `certbot renew --cert-name saliystudio.com --dry-run` успешна, автопродление настроено Certbot.

Конфигурации:

- `/etc/nginx/sites-available/saliystudio`
- `/etc/nginx/sites-available/admin.saliystudio`

У обеих админок (`admin.saliystudio.com` и прежней `admin.saliyclothes.com`) добавлен прокси `/api/`. Клиент админки собран с `VITE_API_URL=/api`, поэтому cookies авторизации отправляются на собственный домен, без обращения к другому сайту.

Исходные конфигурации и версии до добавления API-прокси сохранены в `/root/saliystudio-domain-20261107T134741Z`.

Скрипты, использованные при настройке:

- [configure-saliystudio-nginx.sh](../ops/configure-saliystudio-nginx.sh) — создание конфигураций и выпуск сертификата.
- [enable-saliy-admin-api.py](../ops/enable-saliy-admin-api.py) — API-прокси админок.

## Приложения

В `.env` backend и окружении PM2 обновлены только публичные адреса:

```dotenv
FRONTEND_URL=https://saliystudio.com
BACKEND_URL=https://saliystudio.com/api
```

Новые адреса уже были в `CORS_ORIGINS`. PM2 backend перезапущен с обновлённым окружением; список процессов сохранён через `pm2 save`. Новые платежи формируют URL возврата и webhook с новым доменом. Старые URL по-прежнему доступны для уже созданных платежей.

В витрине обновлены адреса в метаданных, Open Graph, sitemap, robots, карточках товаров и страницах с информацией о магазине. SSR продолжает использовать `API_URL=http://127.0.0.1:3000/api`, браузер — относительный `/api`.

При сборке обнаружено несоответствие исходников витрины текущему backend: оставались вызовы удалённых `/auth/send-code`, `/auth/verify-code`, `/auth/refresh`, `/auth/logout`. В исходниках восстановлен переход на Better Auth: отправка OTP, вход, `get-session`, выход. Удалено обновление JWT и повтор запроса после 401; ошибки Better Auth показываются с сообщением сервера. После входа профиль, как прежде, загружается через `/auth/me`.

Сборки подготовлены отдельно в `/home/deploy/releases/domain-saliystudio-20261107`, затем переключены рабочие `.next` и `dist`. Старые хешированные JS/CSS сохранены для уже открытых страниц. Зависимости не обновлялись. Сборка backend и миграции БД не запускались; локальные изменения предзаказов этой операцией не выкладывались.

Патчи для переноса изменений в отдельный репозиторий витрины, в указанном порядке:

1. [storefront-saliystudio-domain.patch](patches/storefront-saliystudio-domain.patch)
2. [storefront-better-auth-reconcile.patch](patches/storefront-better-auth-reconcile.patch)

## Перенаправление старого магазина (подготовлено, ещё не применено)

`ops/redirect-saliyclothes.py` загружен на сервер как `/home/deploy/redirect-saliyclothes.py`.
Проверка `python3 /home/deploy/redirect-saliyclothes.py --check` прошла на текущей
конфигурации. Для применения нужен запуск на сервере:

```bash
sudo python3 /home/deploy/redirect-saliyclothes.py
```

Скрипт сохраняет резервную копию в `/root/saliyclothes-redirect-*`, проверяет
`nginx -t`, применяет reload и восстанавливает конфигурацию при ошибке.
Страницы HTTP/HTTPS у `saliyclothes.com` и `www.saliyclothes.com` получают 301
на `https://saliystudio.com$request_uri`. API и HTTPS-статика сохраняются для
ранее созданных платежей и уже открытых страниц. HTTP `/api/` получает 308 на
собственный HTTPS-адрес с сохранением метода. Админки не меняются.

Изменения пока не включены: у доступного SSH-пользователя `deploy` sudo требует
пароль. При проверке старый домен ещё возвращал 200, новый — 200.

После применения проверить 301 и Location для обоих старых имён по HTTP/HTTPS,
сохранение пути и query string, отсутствие редиректа у HTTPS `/api/health` и 200
нового магазина.
