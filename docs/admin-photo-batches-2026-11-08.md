# Загрузка произвольного количества фото — 8 ноября 2026

На сервере обновлена админка `/home/deploy/apps/saliy_admin`, обслуживающая
`admin.saliystudio.com` и `admin.saliyclothes.com`.

Причина отказа: серверный Multer допускает 10 файлов `images` в одном запросе,
а интерфейс отправлял весь выбор сразу. На 11-м файле возникала ошибка
`400 Unexpected field - images`.

В сервисе товаров запросы теперь выполняются последовательно партиями:
не более 10 файлов и 20 МиБ файловых данных на запрос. Количество выбранных
фото не ограничивается. Проверка всех файлов выполняется до первого запроса;
для отдельного фото сохраняются поддерживаемые форматы JPG/PNG/WebP и лимит
10 МиБ. Эти ограничения не зависят от числа фото.

Изменение действует при добавлении фото и создании товара. При создании первая
партия передаётся вместе с данными товара, сохраняя штатное назначение превью.
Остальные партии добавляются последовательно. Если создание уже состоялось,
но последующая загрузка прервалась, интерфейс открывает созданный товар и
показывает сообщение о частично загруженных фото.

При редактировании подтверждённые партии исключаются из очереди, чтобы повтор
после ошибки не отправлял их заново. Изменение порядка галереи сохраняется
до добавления новых фото: сервер заменяет массив при изменении порядка, и
прежняя последовательность могла исключить только что добавленные фото.
Подтверждённые удаления также исключаются из очереди повторной попытки.
При потере ответа сервера результат отдельного запроса остаётся неопределённым;
полная идемпотентность загрузки не добавлялась.

Патч относительно существовавших серверных исходников:
[admin-photo-batches.patch](patches/admin-photo-batches.patch).

Проверки с подменённым транспортом: 37 фото, партии по размеру (файлы по 8 МиБ),
порядок, последовательность запросов, предварительная проверка формата и размера,
ошибка второй партии, создание с 23 фото и ошибка после создания товара.
Все прошли. Реальные фото в товары для проверки не добавлялись.

Изолированная сборка TypeScript + Vite прошла в
`/home/deploy/releases/photo-batches-20261108`. Рабочая админка отдаёт новую
сборку `index-Bo0RxSkj.js`; скрипт доступен с обоих доменов с кодом 200.
Backend health — 200. Backend, схема БД и миграции не менялись.
Старые хешированные ресурсы сохранены для открытых вкладок.

Резервная копия трёх изменённых исходников и предыдущего `dist`:
`/home/deploy/backups/photo-batches-20261108`. При откате восстановить исходники
и `dist` вместе. Пользователю нужно обновить страницу админки.

## Повторное зависание на iPhone

После первого обновления менеджер сообщил о нескольких минутах «Сохранение».
В backend есть успешные GET карточки с iPhone после обновления, но нет
завершённых POST загрузки с этого телефона за соответствующий период.
Запросы с компьютера в это время успешно загружали фото. CPU и память не
указывали на перегрузку. Логи Nginx недоступны пользователю deploy, поэтому
причина остановки передачи с телефона не установлена. Отсутствие POST в логе
завершённых запросов само по себе не доказывает, что запрос вообще не начинался.

У frontend fetch отсутствовал таймаут. Добавлена граница ожидания multipart
120 секунд, включая чтение ответа; при сохранении параметров товара, удалении
фото и сохранении порядка — 30 секунд. Другие запросы без явно заданного таймаута
сохраняют прежнее время ожидания. Сообщение при сетевой ошибке/таймауте просит
обновить карточку и проверить сохранённые фото перед повтором: оборванный ответ
не гарантирует, что сервер не успел сохранить файл.

Редактирование отправляет по одному фото; создание — по два для сохранения
штатного назначения primary/hover. Количество выбранных фото не ограничено.
Кнопки создания и сохранения показывают число подтверждённых фото `Фото N/M`.
Это счётчик завершённых файлов, а не процент передачи байтов.

Подтверждены тестами зависший fetch, зависшее чтение ответа, обрыв соединения,
ошибки API и очистка таймеров, а также прежние сценарии загрузки партиями.
TypeScript + Vite успешно собраны и опубликованы без перезапуска backend.
Позже владелец уточнил: менеджер смог загрузить фото с телефона, но загрузка
остаётся очень медленной. Успешная загрузка отмечена по сообщению владельца;
причина низкой скорости не установлена.

Сборка: `/home/deploy/releases/photo-timeout-20261108`, ресурс

`/home/deploy/backups/photo-timeout-20261108`.
