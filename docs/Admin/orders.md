# API админ-панели: Заказы

Предзаказы оформляются и отправляются как обычные заказы (сразу `CONFIRMED`, накладная СДЭК), см. [Предзаказы](../shop/preorders.md).

**Базовый URL:** `/api/admin/orders`

**Авторизация:** все эндпоинты требуют авторизации администратора (`AdminGuard`). Запросы авторизуются через httpOnly cookie `adminToken`, которую браузер отправляет автоматически.

---

## 1. Статистика заказов

**GET** `/api/admin/orders/stats`

Общая статистика по заказам для дашборда.

| Поле ответа | Описание |
|-------------|----------|
| `totalOrders` | Всего заказов |
| `paidOrders` | Оплаченных заказов |
| `todayOrders` | Заказов за сегодня |
| `totalRevenue` | Общая выручка (оплаченные, без отменённых) |
| `byStatus` | Распределение заказов по статусам |

---

## 2. Список заказов

**GET** `/api/admin/orders`

Список всех заказов с фильтрами и пагинацией.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `status` | OrderStatus | Фильтр по статусу (PENDING, CONFIRMED, etc.) |
| `isPaid` | boolean | Только оплаченные / неоплаченные |
| `search` | string | Поиск по номеру заказа, имени, email, телефону |
| `dateFrom` | ISO date | Заказы от даты |
| `dateTo` | ISO date | Заказы до даты |
| `page` | number | Номер страницы (default 1) |
| `limit` | number | Размер страницы (default 20) |

Ответ: объект с полями `orders` (массив заказов с `items` и `promoCode`) и `pagination` (`page`, `limit`, `total`, `totalPages`). CDEK-поля (см. ниже) присутствуют в каждом заказе.

## 3. Получить заказ по номеру

**GET** `/api/admin/orders/:orderNumber`

Детальная информация о заказе, включая данные пользователя (если был авторизован), состав (`items`) и промокод.

### CDEK-поля (где заказ сейчас)

| Поле | Описание |
|------|----------|
| `cdekNumber` | Номер накладной CDEK (для отображения клиенту) |
| `cdekUuid` | Внутренний идентификатор CDEK |
| `cdekStatus` | Текущий код статуса из CDEK (см. маппинг ниже) |
| `cdekStatusName` | Человекочитаемое название статуса |
| `cdekStatusDate` | Когда статус получен (из webhook или ручного refresh) |
| `cdekTrackingUrl` | Готовая ссылка для клиента, `null` если накладная ещё не выписана |
| `cancelReason` | Причина отмены/неоплаты заказа или запись о последнем возврате денег, `null` если заказ нормальный |
| `refundedAmount` | Сколько рублей уже вернули покупателю (сумма всех возвратов), `0` если возвратов не было |

Накладная CDEK создаётся автоматически при подтверждении оплаты заказа с доставкой CDEK — после этого появляется `cdekUuid`, затем `cdekNumber` (трек-номер) и статусы доставки приходят через webhook CDEK на наш эндпоинт `POST /api/delivery/webhook`. Статус «где посылка сейчас» виден в полях `cdekStatus` / `cdekStatusName`, трек-ссылка — в `cdekTrackingUrl`. Обновить статус вручную — `POST /api/admin/orders/:orderNumber/cdek/refresh`.

Подписка на вебхуки CDEK регистрируется только через API CDEK (не в личном кабинете): запросом на адрес вебхуков CDEK с типом события «статус заказа» и нашим URL уведомлений. Для защиты от подделки URL содержит секрет (`CDEK_WEBHOOK_SECRET`): вебхук регистрируется на `https://saliyclothes.com/api/delivery/webhook/<секрет>`, запросы без верного секрета отклоняются. CDEK присылает статусы и по чужим заказам в рамках договора — такие тихо игнорируются (заказ не найден в нашей БД).

### Накладная CDEK: ручное создание и печать

- `POST /api/admin/orders/:orderNumber/cdek/create` — создать накладную CDEK для заказа вручную (если не создалась автоматически при оплате, например для старых заказов). Ошибка, если у заказа не CDEK-доставка, накладная уже есть или нет кода города.
- `POST /api/admin/orders/cdek/create-missing` — массово создать накладные для ВСЕХ оплаченных CDEK-заказов без накладной. Возвращает сводку: сколько всего, сколько создано, какие не удались.
- `POST /api/admin/orders/:orderNumber/cdek/recreate` — пересоздать накладную: удалить старую в CDEK и создать новую с актуальным составом/размерами. Только если посылка ещё не уехала. Трек-номер сменится.
- `POST /api/admin/orders/cdek/recreate-all` — массово пересоздать накладные у всех неуехавших заказов (например чтобы у старых накладных появился размер в названии). Уехавшие пропускаются. Сводка: пересоздано/пропущено/ошибки. ВНИМАНИЕ: трек-номера у пересозданных сменятся.

При пересоздании накладной старая в CDEK удаляется (`DELETE /v2/orders/{uuid}`), чтобы не копились дубли-черновики. То же происходит при смене состава заказа.

Трек-номер CDEK (`cdekNumber`) присваивается не сразу: при создании накладной заказ в статусе «Принят», номер появляется когда CDEK обрабатывает накладную дальше. Он приходит через webhook ORDER_STATUS; дополнительно фоновая задача раз в 10 минут добирает номер для заказов с накладной, но без номера (подстраховка к webhook). Пока номера нет — `cdekTrackingUrl` будет `null`, это нормально.
- `GET /api/admin/orders/:orderNumber/waybill.pdf` — скачать квитанцию (накладную) CDEK в PDF для сдачи посылки в ПВЗ. Требует, чтобы накладная уже была создана (есть `cdekUuid`). Форма готовится несколько секунд — запрос может занять до ~15 секунд.

Отправитель в накладной (имя и телефон) задаётся переменными `CDEK_SENDER_NAME` и `CDEK_SENDER_PHONE`.

В накладной CDEK у позиции товара к названию добавляется размер в скобках, например «SALIY DENIM JACKET BLACK (L)» — у CDEK нет отдельного поля размера, поэтому отправитель видит, какой размер класть, прямо в названии. Действует для накладных, создаваемых после этой доработки.

Поле `cancelReason` заполняется автоматически, когда заказ становится отменённым или неоплаченным, и показывает почему: «Не оплачен в течение N мин — автоотмена» (клиент не успел оплатить), «Платёж отклонён платёжной системой» / «Оплата отменена / истёк срок платёжной ссылки» (отказ от Точки/Яндекса), «Ошибка регистрации платежа …» (не удалось создать ссылку), «Отменён администратором: …» (ручная отмена). При успешной оплате причина очищается.

## 4. Обновить поля заказа

**PATCH** `/api/admin/orders/:orderNumber`

Обновление произвольных полей заказа (контакты клиента, адрес, доставка, комментарий). Все поля опциональны — передавайте только те, что нужно изменить. Этот эндпоинт **не** меняет `status` и `total`.

### Доступные поля

Клиент:

| Поле | Тип | Описание |
|------|-----|----------|
| `firstName` | string | Имя |
| `lastName` | string | Фамилия |
| `phone` | string | Телефон |
| `email` | string | Email |
| `socialContact` | string | Контакт в соцсети/мессенджере |
| `comment` | string | Комментарий к заказу |

Адрес:

| Поле | Тип | Описание |
|------|-----|----------|
| `countryName` | string | Страна |
| `regionName` | string | Регион |
| `cityName` | string | Город |
| `cdekCityCode` | number | Код города CDEK |
| `street` | string | Улица |
| `apartment` | string | Квартира |
| `postalCode` | string | Индекс |
| `pickupPoint` | string | Код ПВЗ |

При самовывозе CDEK (`deliveryType=CDEK_PICKUP`) фронт присылает только код ПВЗ (`pickupPoint`). Backend автоматически подтягивает из CDEK по этому коду адрес пункта и заполняет `cityName`, `regionName`, `postalCode` и `street` (полный адрес ПВЗ), если они пришли пустыми. Так в админке виден читаемый адрес выдачи, а не только код вида `CHEL47`.

Доставка и оплата:

| Поле | Тип | Описание |
|------|-----|----------|
| `deliveryType` | enum | CDEK_PICKUP / STANDARD |
| `paymentMethod` | enum | SBP_TOCHKA / YANDEX_PAY (активны); CARD_ONLINE / CARD_MANUAL / CRYPTO / PAYPAL (прочие) |
| `deliveryPrice` | number | Цена доставки (>= 0) |
| `deliveryTotal` | number | Итог по доставке (>= 0) |
| `isPaid` | boolean | Признак оплаты |
| `paymentId` | string | ID платежа |

Ответ: обновлённый объект заказа. Ошибки: `404` — заказ не найден.

### Автосинхронизация с CDEK

Если у заказа уже есть `cdekUuid` (накладная создана в CDEK) и через PATCH меняются релевантные для CDEK поля — изменения автоматически пушатся в CDEK (`PATCH /v2/orders/{uuid}`).

| Поле в нашем PATCH | Что меняется в CDEK |
|--------------------|---------------------|
| `firstName`, `lastName` | `recipient.name` (склеиваются) |
| `phone` | `recipient.phones[].number` |
| `email` | `recipient.email` |
| `comment` | `comment` накладной |
| `pickupPoint` (при `deliveryType=CDEK_PICKUP`) | `delivery_point` (код ПВЗ) |
| `cdekCityCode`, `street`, `apartment` (при `deliveryType=CDEK_COURIER`) | `to_location` (город/адрес) |

CDEK позволяет менять данные только пока посылка не уехала со склада отправителя. Если статус уже `TAKEN_BY_TRANSPORTER_FROM_SENDER_CITY` или дальше — CDEK откажет. В этом случае запись в нашей БД всё равно обновится (`200 OK`), а в ответе появится поле `cdekSyncError` с текстом ошибки от CDEK. Если `cdekUuid` отсутствует (накладная ещё не создана) — синхронизации нет.

## 4.1. Изменить состав заказа (товары)

**PUT** `/api/admin/orders/:orderNumber/items`

Полностью заменяет позиции заказа: можно менять размер и количество, удалять и добавлять товары. В теле передаётся новый список позиций — каждая позиция это `productId`, `size`, `quantity`. Цены берутся из базы (не от клиента).

Что делает backend в одной транзакции: возвращает на склад товар по старым позициям, проверяет наличие и списывает по новым (если товара не хватает — ошибка, ничего не меняется), пересоздаёт позиции со снэпшотом цен, пересчитывает сумму заказа (`subtotal` и `total`). Скидка по промокоду и стоимость доставки не меняются.

Ограничения: нельзя менять состав отменённого, возвращённого или доставленного заказа. Накладная CDEK при смене состава автоматически не пересоздаётся — если посылка ещё не отправлена и состав сильно изменился, накладную создают заново вручную.

## 4.2. Изменить оплату заказа (способ / отметка оплаты)

**PATCH** `/api/admin/orders/:orderNumber/payment`

Позволяет менеджеру вручную сменить способ оплаты и/или отметить заказ оплаченным. Поля (оба опциональны): `paymentMethod` (новый способ) и `paid` (true/false).

Типовой кейс: клиент не смог оплатить онлайн (например Сплит не прошёл), написал и оплатил по реквизитам — менеджер ставит способ `BANK_TRANSFER` и `paid: true`. При отметке оплаты срабатывают те же действия, что при обычной оплате: чек на почту, очистка корзины, создание накладной CDEK (идемпотентно). Можно сменить только способ, оставив заказ неоплаченным (`paid` не передавать) — тогда заказ ждёт оплату и подтвердится сам, когда она придёт.

`BANK_TRANSFER` (оплата по реквизитам) — служебный способ только для админки, на витрине магазина в выборе не показывается.

## 4.3. Создать заказ вручную (менеджером)

**POST** `/api/admin/orders`

Менеджер создаёт заказ от лица клиента (заказ пришёл в личку/соцсети). В теле: список товаров (`items` — `productId`, `size`, `quantity`), данные клиента (имя, фамилия, телефон, почта, соцсеть), тип доставки и адрес/ПВЗ, способ оплаты, и флаг `paid` (оплачен ли уже). Цены и остатки берутся из базы, сток списывается. Если `paid: true` — заказ сразу подтверждается (чек, накладная CDEK); если нет — остаётся в ожидании оплаты (ручные заказы автоотмена по таймауту не трогает — она только для онлайн-оплат). Для самовывоза CDEK адрес ПВЗ подтягивается автоматически по коду пункта.

## 5. Изменить статус заказа

**PATCH** `/api/admin/orders/:orderNumber/status`

Обновить статус заказа. Нельзя менять статус отменённых заказов.

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `status` | OrderStatus | Да | Новый статус |

Доступные статусы: `PENDING`, `PAYMENT_FAILED`, `CONFIRMED`, `PROCESSING`, `SHIPPED`, `DELIVERED`, `CANCELLED` (для отмены используйте отдельный эндпоинт), `REFUNDED`.

Ответ: обновлённый объект заказа. Ошибки: `404` — заказ не найден, `400` — попытка изменить статус отменённого заказа.

## 6. Отменить заказ (кнопка «Отменить заказ»)

**POST** `/api/admin/orders/:orderNumber/cancel`

Отменяет заказ: возвращает товар на склад (размеры снова доступны для покупки), уменьшает счётчик `salesCount` у товаров, ставит `status: CANCELLED` и записывает причину в `cancelReason`. Всё выполняется в транзакции.

Если у заказа есть накладная CDEK и посылка ещё не уехала со склада отправителя, накладная автоматически удаляется в CDEK, CDEK-поля заказа обнуляются. Если CDEK не дал удалить накладную, в логах появится предупреждение, и её удаляют вручную в кабинете CDEK.

**Деньги отмена не возвращает.** Если заказ был оплачен, после отмены у него остаётся `isPaid: true`, и админка должна предложить вернуть деньги кнопкой «Вернуть деньги» (раздел 7).

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `reason` | string | Нет | Причина отмены — сохраняется в `cancelReason` |

Ответ: обновлённый заказ со `status: CANCELLED`.

Ошибки:

| Код | Когда |
|-----|-------|
| 404 | Заказ не найден |
| 400 | Заказ уже отменён |
| 400 | Заказ уже отправлен или доставлен — отменить нельзя, только вернуть деньги |
| 400 | Резерв уже освобождён (заказ не оплачен вовремя, оплата отклонена или по нему уже сделан полный возврат) |

## 7. Вернуть деньги (кнопка «Вернуть деньги»)

**POST** `/api/admin/orders/:orderNumber/refund`

Возвращает покупателю деньги — всю сумму или часть.

- **Заказ оплачен через Т-Банк** (`paymentMethod: CARD_ONLINE`): деньги возвращаются через API Т-Банка на карту, с которой платили. Заходить в кабинет банка не нужно.
- **Другие способы оплаты** (перевод, оплата через менеджера и т. п.): деньги возвращают вручную, а здесь только отмечают возврат, передав `manual: true`. Без этого флага бэкенд ответит 400 и в банк не пойдёт.

Тело запроса:

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `reason` | string | Да | Причина возврата, до 500 символов |
| `amount` | number | Нет | Сколько вернуть, в рублях, до 2 знаков после запятой. Не передано — возвращается весь остаток: `total − refundedAmount` |
| `manual` | boolean | Нет | `true` — деньги вернули вручную, бэкенд только записывает возврат и в банк не обращается |

Что происходит:

- **Полный возврат** (вместе с прошлыми возвратами вернули всю сумму `total`): заказ получает `status: REFUNDED`, `isPaid: false`. Если товар ещё не отправлен и заказ не отменяли, товар возвращается на склад, а неотправленная накладная CDEK удаляется. Если заказ уже отменили кнопкой «Отменить заказ», товар второй раз не возвращается.
- **Частичный возврат**: статус заказа и склад не меняются, растёт только `refundedAmount`. Остаток можно вернуть следующим запросом.
- **Отправленный или доставленный заказ**: деньги возвращаются, товар на склад — нет, потому что вещь уже у покупателя или в пути.
- В `cancelReason` записывается последняя операция, например «Возврат 18700 ₽ через Т-Банк: причина».
- Покупателю уходит письмо о возврате с суммой.

Защита: строка заказа блокируется на время запроса в банк, поэтому двойное нажатие не вернёт деньги дважды. Сумму больше оставшейся вернуть нельзя.

Т-Банк не принимает возврат меньше 1 ₽ (100 копеек) и отвечает ошибкой 502 «Неверная сумма. Сумма должна быть больше или равна 100 копеек». Поэтому в окне возврата минимальная сумма — 1 ₽.

Ответ:

| Поле | Описание |
|------|----------|
| `order` | Обновлённый заказ, включая `status`, `isPaid`, `refundedAmount`, `cancelReason` |
| `refund.amount` | Сколько вернули этим запросом, ₽ |
| `refund.refundedTotal` | Сколько всего вернули по заказу, ₽ |
| `refund.full` | `true`, если вернули всю сумму заказа |
| `refund.stockReturned` | `true`, если товар вернулся на склад |
| `refund.viaBank` | `true` — деньги отправлены через Т-Банк, `false` — отмечен ручной возврат |

Ошибки:

| Код | Когда |
|-----|-------|
| 404 | Заказ не найден |
| 400 | Заказ не оплачен — возвращать нечего |
| 400 | Деньги по заказу уже возвращены полностью |
| 400 | Сумма больше оставшейся («Можно вернуть не больше N ₽») или некорректная |
| 400 | Заказ оплачен не через Т-Банк, а `manual: true` не передан |
| 502 | Т-Банк отказал. В тексте ошибки причина от банка, её нужно показать админу как есть. Деньги не вернулись, в заказе ничего не изменилось |
| 502 | «Т-Банк временно недоступен» — нет ответа от банка. Перед повтором проверить платёж в кабинете Т-Банка: банк мог успеть выполнить возврат |

Если деньги вернули прямо в кабинете Т-Банка, банк сам пришлёт уведомление о полном возврате: заказ станет `REFUNDED`, `refundedAmount` станет равен `total`, а неотправленный товар вернётся на склад. Частичный возврат из кабинета бэкенд не записывает — такие возвраты лучше делать кнопкой в админке.

Смена статуса на `REFUNDED` через `PATCH /api/admin/orders/:orderNumber/status` только отмечает возврат (как `manual: true`) и деньги не двигает.

### Что показывать в админке

- Кнопка **«Отменить заказ»** — пока заказ не отправлен и не отменён: статус не `CANCELLED`, `REFUNDED`, `PAYMENT_FAILED`, `SHIPPED`, `DELIVERED`. Перед вызовом подтверждение с полем причины.
- Кнопка **«Вернуть деньги»** — когда `isPaid: true` и `refundedAmount < total`, в том числе у отменённого оплаченного заказа. В окне: сумма (по умолчанию остаток `total − refundedAmount`, можно уменьшить), причина (обязательна), подтверждение «Вернуть N ₽ покупателю?». Для заказов не через Т-Банк — галочка «Деньги вернул вручную» (`manual: true`).
- В карточке заказа: «Возвращено: `refundedAmount` ₽ из `total` ₽», если `refundedAmount > 0`.
- Ошибку 502 от возврата показывать текстом из ответа: там причина от банка.
- Порядок для оплаченного неотправленного заказа: «Отменить заказ», затем «Вернуть деньги». Можно и сразу «Вернуть деньги» на всю сумму: заказ получит `REFUNDED`, товар вернётся на склад.

## 8. Обновить CDEK-информацию

**PATCH** `/api/admin/orders/:orderNumber/cdek`

Ручное обновление CDEK-данных заказа (например, после создания накладной в панели CDEK). Все поля опциональны.

| Поле | Тип | Описание |
|------|-----|----------|
| `cdekNumber` | string | Номер накладной |
| `cdekUuid` | string | UUID заказа в CDEK |
| `cdekStatus` | string | Код статуса |
| `cdekStatusName` | string | Название статуса |

При передаче `cdekStatus` автоматически обновляется `cdekStatusDate`.

## 8.1. Подтянуть актуальный статус из CDEK

**POST** `/api/admin/orders/:orderNumber/cdek/refresh`

Когда webhook потерялся / не настроен — админ запрашивает у CDEK статус напрямую по `cdekUuid` (или `cdekNumber`) и сохраняет в БД.

Что делает: берёт идентификатор заказа, запрашивает `GET /orders/{identifier}` в CDEK, берёт последний статус из `entity.statuses`, обновляет `cdekStatus`, `cdekStatusName`, `cdekStatusDate` и `status` (если CDEK-статус маппится в продвижение вперёд). Не понижает статус заказа.

Ответ содержит: `orderNumber`, `cdekStatus`, `cdekStatusName`, `cdekStatusDate`, `status`, `trackingUrl`.

Ошибки:

| Код | Описание |
|-----|----------|
| 404 | Заказ N не найден |
| 404 | У заказа N нет CDEK-идентификаторов (ещё не создана накладная) |

## 8.2. Webhook от CDEK

**POST** `/api/delivery/webhook` — **не под AdminGuard**, принимает уведомления от CDEK напрямую.

CDEK присылает уведомление с типом `ORDER_STATUS`, идентификатором заказа (`uuid`) и атрибутами (`cdek_number`, `code`, `name`, `date_time`).

Поведение бэка: ищет заказ по `cdekUuid` или `cdekNumber`; обновляет `cdekStatus`/`cdekStatusName`/`cdekStatusDate`; маппит статус CDEK на `OrderStatus` и меняет, если это продвижение вперёд и заказ не отменён/не возвращён.

Настройка webhook в личном кабинете CDEK: URL `https://saliyclothes.com/api/delivery/webhook`, тип события `ORDER_STATUS`, метод `POST`.

### Маппинг CDEK → OrderStatus

| CDEK код | Описание | Наш статус |
|----------|----------|-----------|
| `CREATED`, `ACCEPTED` | Заказ создан/принят | `CONFIRMED` |
| `RECEIVED_AT_SHIPMENT_WAREHOUSE`, `READY_FOR_SHIPMENT_IN_SENDER_CITY` | На складе | `PROCESSING` |
| `TAKEN_BY_TRANSPORTER_*`, `SENT_TO_*`, `ACCEPTED_IN_TRANSIT_CITY`, `ACCEPTED_AT_RECIPIENT_CITY_WAREHOUSE`, `ACCEPTED_AT_PICK_UP_POINT`, `READY_TO_BE_HANDED_OVER`, `TAKEN_BY_COURIER` | В пути / прибыл в ПВЗ / у курьера | `SHIPPED` |
| `RECEIVED`, `DELIVERED` | Вручён | `DELIVERED` |
| `NOT_DELIVERED` | Не доставлен | `CANCELLED` |
| `RETURNED`, `RETURNED_TO_SENDER` | Возврат | `REFUNDED` |

## OrderStatus — жизненный цикл заказа

Обычный заказ: PENDING → CONFIRMED → PROCESSING → SHIPPED → DELIVERED → (REFUNDED). Оплаченный заказ можно отменить (CANCELLED) до отправки и затем вернуть деньги (REFUNDED); частичный возврат статус не меняет. Предзаказ — так же, как обычный заказ. Из PENDING возможен переход в PAYMENT_FAILED. Отмена доступна до отправки.
