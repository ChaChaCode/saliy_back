# Боевой терминал Т-Банка — 3 ноября 2026

Backend переключён с DEMO-терминала на боевой, frontend обновлён до версии с оплатой
через Т-Банк. Первый реальный заказ `SALIY26110300002` оплачен и подтверждён.

## Что выложено

- **Ключи терминала.** В `.env` backend записаны боевые `TBANK_TERMINAL_KEY` и
  `TBANK_PASSWORD`; адрес API банка не менялся. Значения в репозиторий не попадают.
- **Frontend.** Серверная копия магазина обновлена до коммита `d16019a`
  (оплата `CARD_ONLINE`). CI на GitHub Actions этот коммит не выложил, поэтому
  сборка сделана на сервере в отдельной рабочей копии и подменена после проверки.
  Поверх применён [патч свежести данных](./patches/storefront-fresh-data.patch):
  запросы к API без кеша, главная и каталог без ISR (новый товар виден сразу).
  SSE-подписка открытых вкладок удалена из магазина и backend
  (см. [свежесть данных](./live-cache-updates.md)). Патча ещё нет в репозитории
  магазина, и следующий деплой через CI его затрёт.
- **Возврат остатков при неуспешной оплате.** Отказ банка, отмена платежа и ошибка
  Init сразу возвращают товар на склад (подробности в [описании оплаты](./shop/payment.md)).
  Раньше заказ в PAYMENT_FAILED держал бронь бессрочно: автоотмена смотрит только PENDING.
- **Бесплатная доставка по промокоду.** Промокод FREE_DELIVERY теперь обнуляет
  доставку в расчёте и в заказе; раньше доставка оставалась в сумме.
- **Админка.** `CARD_ONLINE` подписан как «Т-Банк (карта)»; Точка и Яндекс Пэй убраны
  из ручного выбора способа оплаты (у старых заказов текущий способ остаётся в списке);
  добавлена подпись «Оплата по реквизитам». Правка сделана в серверной копии админки,
  её нужно перенести в репозиторий админки: [патч](./patches/admin-payment-labels.patch).
- **Админка: подгрузка списков и красные кнопки.** Бесконечная прокрутка заказов,
  пользователей и подписчиков не подгружала следующие страницы при первом открытии:
  наблюдатель создавался до появления элемента-стража (на его месте был лоадер).
  Теперь он подключается, когда страж появляется, и перепроверяет видимость после
  каждой подгрузки. Кнопки удаления получили вариант `danger` (полупрозрачный красный фон,
  красный текст): прежние классы конфликтовали с базовыми цветами кнопки, и текст
  оставался белым на бледно-розовом фоне. [Патч](./patches/admin-scroll-danger.patch).
- **Статусы СДЭК.** Ручное и фоновое обновление статуса брало последний элемент
  истории СДЭК, а она отдаётся от новых к старым, то есть брался самый старый статус.
  Теперь берётся статус с самой поздней датой. 21 июньский заказ, вручённый 27–30 июня,
  висел «В обработке»: webhook за эти дни до сервера не дошли. Статусы восстановлены
  по данным СДЭК, прежние значения сохранены в `back-cdek-latest-status-*`.
- **Рассылки.** Кнопка «Уведомить подписчиков» на странице товара (письмо о товаре
  один раз на товар, отметка `newsletterSentAt`, миграция `20261103170000`) и страница
  «Рассылки» в админке. Исправлены двойной запуск кампании и учёт писем, не принятых
  SMTP. Подробности в [описании кампаний](./Admin/campaigns.md). Админка —
  [патч](./patches/admin-campaigns.patch), применяется после трёх предыдущих патчей админки.
- **Админка: ошибка после удаления.** После любой мутации админка перечитывает все
  данные, в том числе только что удалённую категорию, товар, баннер, промокод или
  пользователя, получала 404 и показывала «Не удалось загрузить». Удаление теперь
  помечает ключ удалённого объекта, и его не перечитывают.
  [Патч](./patches/admin-delete-refetch.patch) применяется последним.
- **Админка: описание категории.** Форма создания и редактирования категории отправляла
  поле «Описание», которого нет ни в базе, ни в API, поэтому создание и любое сохранение
  категории отклонялись с ответом 400. Поле убрано (витрина его не показывает), ошибки
  показывают причину от backend. [Патч](./patches/admin-category-description.patch).
- **Рассылка при создании товара.** Галочка «Разослать подписчикам» в форме создания
  товара (по умолчанию выключена). [Патч](./patches/admin-create-notify.patch) — седьмой.
- **Авторизация только в httpOnly-куках.** Backend больше не возвращает access-токен
  в теле ответа и не принимает заголовок `Authorization` (покупатели и админка); витрина
  перестала хранить токен в JavaScript ([патч](./patches/storefront-auth-cookies.patch),
  применяется после `storefront-fresh-data.patch`). Ошибки 4xx в логе — `WARN`,
  `ERROR` остаётся для 5xx. 4 ноября 2026 весь прежний вход (JWT, refresh-токены,
  свои коды) заменён Better Auth — см. [вход через Better Auth](./shop/better-auth.md).
- **Диагностика webhook.** При неверной подписи логируются имена и типы полей,
  Status и TerminalKey. Значения карты и токен не логируются.

## Ловушка с окружением PM2

После записи ключей и перезапуска с флагом обновления окружения процесс продолжил
работать с DEMO-ключом. PM2 хранит окружение, переданное при прошлом обновлении,
а dotenv не перезаписывает уже заданные переменные. Флаг обновления берёт окружение
вызывающей оболочки, поэтому значения из `.env` нужно сначала загрузить в неё.

Последствия до исправления:

- заказ `SALIY26110300001` создан через DEMO-терминал, и реальная карта отклонена;
- уведомления по платежам боевого терминала отклонялись как «Неверная подпись».

Порядок после любой правки `.env`:

1. Загрузить переменные из `.env` в оболочку, затем перезапустить `saliy_back`
   с обновлением окружения и сохранить состояние PM2.
2. Сверить нужную переменную в окружении работающего процесса (`/proc/<pid>/environ`),
   а не отдельным скриптом, читающим `.env`.

## Открытые вопросы

- Фискализация: Receipt не передаётся. Если на терминале включат онлайн-чеки,
  Init начнёт отклоняться без него.
- Возврат по уже оплаченному заказу обрабатывается только уведомлением банка:
  минутная проверка смотрит лишь PENDING.
- Перенести `storefront-fresh-data.patch` в репозиторий магазина и выяснить, почему CI
  не выложил `d16019a`.
- Перенести в репозиторий админки патчи по порядку: перечитывание после изменений (`admin-live-cache`), подписи
  способов оплаты, прокрутка и красные кнопки, рассылки, ошибка после удаления, описание категории, рассылка при создании товара.
- Старая админка `saliyadmin.vercel.app` обращается к отключённому API
  `saliystudio.com`; рабочая — `admin.saliyclothes.com`.
