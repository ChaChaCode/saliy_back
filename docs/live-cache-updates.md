# Обновление магазина после изменений в админке

Выложено 31 октября 2026 в backend, frontend и админку.

## Поведение

- API возвращает `Cache-Control: no-store` для `/api` (SSE использует `no-cache, no-transform`).
- Общий API-клиент магазина использует `fetch(..., { cache: 'no-store' })` на сервере и в браузере.
  Прежние параметры `revalidate: 60` в отдельных сервисах больше не включают кэш.
- Каталог и товарные страницы рендерятся по запросу, без минутного ожидания обновления.
- Backend сообщает об успешных изменениях через `GET /api/storefront/changes` (SSE).
  Передаётся только пустое событие `change`, без содержимого заказа, товаров или персональных данных.
- Подписаны POST/PUT/PATCH/DELETE в `/api/admin/*`, кроме auth и Telegram webhook,
  а также изменения через публичные контроллеры products/categories/reviews.
  Ошибочный запрос не отправляет событие. Чтения, корзина и вход не запускают обновление витрины.
- Открытая вкладка магазина по событию сбрасывает React Query и вызывает `router.refresh()`
  с объединением событий в окно 150 мс. При возвращении во вкладку и восстановлении
  SSE-соединения данные также перечитываются. Скрытые вкладки обновляются при возвращении.
- Админка после любой успешной React Query mutation инвалидирует запросы;
  staleTime по умолчанию 0, повторный фокус также обновляет устаревшие данные.
- Статические CSS/JS и медиа сохраняют свою политику кэширования.
  Служебные кэши авторизации, блокировок и внешних токенов не очищаются.

Уже открытые до выкладки вкладки нужно один раз перезагрузить, чтобы они загрузили
новый JS с подпиской. Затем изменения, сделанные через перечисленные API, видны после
доставки события и загрузки свежих данных, без ожидания минутного TTL.
Прямые изменения в SQL, файлах сервера или внешнем хранилище не генерируют это событие.

## Исходники frontend: обязательно перенести в репозитории

Поскольку локально доступен только backend, исходники магазина и админки изменены
непосредственно в серверных рабочих копиях. Сохранены переносимые патчи:

- [Магазин](./patches/storefront-live-cache.patch): `src/lib/api.ts`, `src/providers/QueryProvider.tsx`.
- [Админка](./patches/admin-live-cache.patch): `src/api/queryClient.ts`.

В соответствующем репозитории сначала выполнить `git apply --check <путь-к-патчу>`,
потом `git apply <путь-к-патчу>` и сохранить изменения обычным процессом команды.
При конфликте перенести изменения вручную; не перезаписывать параллельные правки.
На сервере они уже применены, повторно применять там не нужно.

Backend-исходники: `src/storefront-sync/`, регистрация модуля в `src/app.module.ts`,
заголовки API и исключение SSE из gzip в `src/main.ts`.

## Проверки и эксплуатация

- 3 тестовых набора backend, 8 тестов прошли локально и на сервере, включая реальный SSE
  в тестовом HTTP-приложении, событие после успешного изменения и отписку при отключении.
- Backend, TypeScript/Vite админки и Next.js магазина собраны успешно отдельно от рабочих приложений.
- Публичные каталог, админка и список товаров: HTTP 200.
- Публичный каталог: `private, no-cache, no-store, max-age=0, must-revalidate`.
- API списка товаров: `Cache-Control: no-store`.
- Через публичный Nginx получен начальный SSE-фрейм без ожидания; SSE исключён из gzip,
  установлено `X-Accel-Buffering: no`, heartbeat раз в 15 секунд, автоматический reconnect.
- Боевой товар ради проверки не изменялся. Проверка события с записью выполнена в изолированном тесте.
- Предыдущие fingerprinted JS/CSS сохранены в новых сборках для старых открытых вкладок.
- Резервная копия исходников и предыдущих сборок:
  `/home/deploy/backups/cache-sync-1793397905480`; файл `deployment.json` содержит пути отката.
- Рабочие приложения `saliy_back` и `saliy_front` перезапущены, PM2-состояние сохранено.
- Данные БД и настройки оплаты не менялись. Т-Банк остаётся в DEMO-режиме.

События реализованы в памяти одного backend-процесса. Текущий PM2 работает в fork mode
с одним экземпляром; для cluster/multi-server понадобится общий брокер событий.
Без кэша нагрузка на API выше; массовые изменения объединяются в браузере, но SSR-запросы
действительно перечитывают данные. Это выбранное поведение для немедленного обновления.
