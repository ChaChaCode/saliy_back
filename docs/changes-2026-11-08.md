## Старая и актуальная цена

- В создании и редактировании товара появились два поля: актуальная цена
  `price` и необязательная старая `oldPrice`.
- Пример: `price: 7000`, `oldPrice: 10000`, `discount: 0` — покупатель видит
  **7 000 ₽** рядом с зачёркнутыми **10 000 ₽**, покупает за **7 000 ₽**.
- Старая цена показывается в каталоге, карточке товара, корзине и checkout.
- При PATCH `oldPrice: null` убирает старую цену. Отсутствие поля сохраняет
  прежнее значение. При создании без старой цены поле можно не отправлять.
- Старая цена должна быть больше актуальной. Новая пара цен передаётся с
  `discount: 0`; прежние товары с процентными скидками продолжают работать.
- В тип товара и ответ проверки корзины добавлено `oldPrice?: number | null`.
  Итоги корзины и заказа брать из API, старую цену в расчёт не включать.

Подробнее: [товары](shop/products.md), [корзина](shop/cart.md),
[админский API](Admin/products.md).

## Размер OS

- В создании и редактировании товара доступен **OS — One Size**.
- Код в остатках, корзине и заказе — `OS`. Пример: `stock: { "OS": 12 }`.
- Витрина получает размеры из ключей `stock`; фиксированный список XS–XL
  не должен скрывать OS. Остаток задаётся отдельно у каждого товара.
- OS повторно восстановлен в обеих формах после последующей публикации сборки
  со старым списком размеров. При переносе изменений в репозиторий включить
  [патч OS](patches/admin-os-size.patch), чтобы следующие сборки сохраняли этот размер.

## Загрузка фото

- Можно выбрать любое количество фото: админка отправляет их последовательно.
- При редактировании — по одному фото за запрос; при создании — первые два
  вместе с товаром, остальные по два через маршрут добавления фото.
- Лимит одного файла — **10 МиБ**, форматы JPG/JPEG, PNG, WebP.
- Добавлены счётчик **«Фото N/M»**, таймаут загрузки 120 секунд и сообщения
  об обрыве соединения. Для сохранения полей, порядка и удаления фото — 30 секунд.
- Подтверждённые партии исключаются из очереди повторной отправки.
  Порядок существующих фото сохраняется до добавления новых.
- Если ответ потерян, перечитать карточку перед повтором: файл мог сохраниться.
- По уточнению владельца, менеджер смог загрузить фото с телефона, но загрузка
  остаётся медленной. Прогресс должен оставаться видимым до завершения запроса.

Серверный контракт остаётся прежним: повторяемое multipart-поле `images`,
до 10 файлов в одном запросе. Ограничение числа выбранных файлов снято за счёт
отправки несколькими запросами, а не увеличения размера одного запроса.
